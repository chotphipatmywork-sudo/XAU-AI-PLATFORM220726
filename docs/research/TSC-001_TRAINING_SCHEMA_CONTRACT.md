# TSC-001 Training Schema Contract

Version: 1.0.0

Status: Draft — Specification only; dataset assembly and training not authorized

Document Type: Research training schema contract

Architecture Baseline: ABR-1.0 (Frozen)

## Purpose

Define the compatible schema requirements for assembling feature and label records into a future training dataset.

## Scope

This contract governs identity joins, feature and label compatibility, column order, types, nullability, partition membership, and dataset identity. It does not redefine feature or label semantics.

## Ownership

The Feature and Label contract owners maintain their respective schemas. The Dataset owner proposes assembly. The Technical Reviewer verifies compatibility. The Project Owner approves the combined schema.

## Inputs

Inputs are accepted feature records governed by FSC-001 and accepted label records governed by LSC-001, joined through the immutable dataset identity and `record_id`, `symbol`, and `timestamp`.

## Outputs

An authorized assembly may produce a versioned combined training schema and partitioned dataset manifest. No dataset is generated by this specification.

## Invariants

Feature and label schema versions must be explicit and compatible. Identity joins must be one-to-one, deterministic, and complete according to the approved population. Labels must not be used as feature inputs. Nulls and missing reasons remain contract-defined.

## Validation Rules

Reject schema-version mismatch, duplicate identities, missing joins, timestamp or symbol disagreement, unexpected columns, invalid types, non-finite values, leakage across partitions, and non-deterministic column ordering.

## Dataset Assembly and Split Policy

Assembly must preserve deterministic record ordering and use DPC-001 chronological, end-exclusive Train, Validation, and Test boundaries. Purge or embargo requirements apply before each boundary. Train may be used for fitting after approval; Validation and Test remain sealed by default.

## Versioning

Any feature or label schema change, join rule, column order, type, partition rule, or null policy change requires a new combined schema version and review.

## Acceptance Criteria

Acceptance requires passing compatibility and partition validation, complete manifest and provenance, immutable dataset identity, independent backup verification, and Project Owner approval.

## References

FSC-001, LSC-001, RDS-001, RFB-001, RDR-001, MMS-001, DLC-001, DPC-001, ELC-001, and DAC-001.

# IMP-072 Fresh Session Hypothesis Confirmation

Version: 1.0.0

Date: 2026-07-19

Status: Confirmation contract implemented; awaiting fresh evidence

Architecture Baseline: ABR-1.0

Related: CR-014, ADR-006, IMP-070, IMP-071

## Purpose and approval boundary

This implementation freezes the two Session observations discovered by
IMP-071 before any later evidence is inspected. It does not change MQL5,
Feature Schema 4.0, Runtime, Risk, Execution, Forward behavior, or deployment.
It cannot authorize broker trading.

The one accepted input name is
`XAU_AI_SETUP_OUTCOME_CONFIRMATION.csv`. Train, Validation, Test, and the
existing complete Dataset are forbidden. Every observation must be strictly
later than the frozen source-evidence boundary `2026.06.26 21:30`.

## Frozen hypotheses

The following directions and thresholds are registered before confirmation:

1. `session_early_phase_positive`: `session_progress < 33.333333` is expected
   to have a higher Target-first rate than its chronological block baseline.
2. `session_late_phase_negative`: `session_progress >= 66.666667` is expected
   to have a lower Target-first rate than its chronological block baseline.

No threshold may be changed after the fresh Dataset is opened. The middle
third remains the unfiltered complement and is not assigned a favorable or
unfavorable claim.

## Source and readiness contract

The confirmation source must be generated by the existing Objective M15/M5
Strategy Tester provider on XAUUSD M15 using `Every tick based on real ticks`,
minimum structural RR 2.0, and the unchanged 64-bar outcome horizon. Any MT5
real-tick quality warnings require a separately reviewed, versioned exclusion
file before the Dataset is built.

The confirmation refuses evaluation unless mature, non-ambiguous evidence has:

- at least 80 plans;
- at least 15 Target-first plans;
- at least 40 non-Target plans.

Quarantined `AMBIGUOUS` and `UNMATURED` rows are counted for source audit but
never enter confirmation metrics.

## Temporal confirmation gate

Ready evidence is divided into four consecutive chronological blocks. Each
hypothesis independently requires:

- at least three matched plans in every block;
- at least 20 matched plans in aggregate;
- the frozen expected Target-rate lift sign in all four blocks;
- at least five percentage points absolute aggregate Target-rate lift.

Both hypotheses must pass to set
`eligible_to_request_stage_2_review: true`. This field requests a human review;
`stage_2_contract_authorized`, Runtime authorization, and deployment remain
false even after a statistical pass.

## One-shot evidence control

The confirmation report stores the source SHA-256. The CLI refuses to overwrite
an existing report because a period is no longer untouched after its outcomes
have been inspected. A failed confirmation may not be tuned and rerun against
the same period. Any later attempt requires a new time boundary and explicit
review.

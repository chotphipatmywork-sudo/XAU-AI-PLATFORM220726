# XAU AI PLATFORM CODEX BEST PRACTICES

Version: 1.0.0

Status: Recommended

Architecture Baseline: ABR-1.0

---

## Purpose

This document defines recommended practices for effective Codex usage within the XAU AI PLATFORM.

These practices are intended to improve development quality, maintain consistency, and support efficient AI-assisted implementation workflows.

This document provides guidance and does not replace mandatory project rules.

---

## Scope

This document applies to Codex-assisted activities, including:

- Code implementation.
- Code review.
- Refactoring.
- Documentation work.
- Technical analysis.

---

## 1. Understand Before Implementing

Before making changes:

- Read the relevant specifications.
- Understand the existing architecture.
- Review affected modules.
- Identify dependencies.
- Confirm expected behavior.

Avoid implementing based only on assumptions.

---

## 2. Keep Changes Focused

Recommended:

- Modify only required files.
- Keep changes within the assigned scope.
- Prefer small incremental improvements.
- Avoid unrelated cleanup.

Focused changes improve:

- Review quality.
- Debugging efficiency.
- Change traceability.

---

## 3. Preserve Architecture

Always:

- Respect module boundaries.
- Maintain dependency direction.
- Reuse existing components.
- Preserve public interfaces.

Avoid:

- Creating duplicate systems.
- Moving responsibilities unnecessarily.
- Introducing alternative architectures.

---

## 4. Prefer Complete Deliverables

For file modifications:

Recommended:

- Provide the complete file.
- Include the full file path.
- Make replacement straightforward.
- Preserve formatting standards.

Avoid:

- Partial implementations.
- Missing sections.
- Unclear modification instructions.

---

## 5. Review Before Delivery

Before returning results:

Perform:

- Self-review.
- Dependency review.
- Naming verification.
- Logic verification.
- Documentation verification.

Ensure the output is ready for project review.

---

## 6. Maintain Documentation Quality

Good documentation should:

- Explain purpose clearly.
- Follow project structure.
- Maintain consistent formatting.
- Avoid duplicated information.
- Reference authoritative documents.

---

## 7. Handle Uncertainty Properly

When information is missing:

Recommended action:

- Identify the missing information.
- Explain the impact.
- Request clarification.

Avoid:

- Guessing requirements.
- Creating hidden behavior.
- Making unauthorized decisions.

---

## 8. Optimize Session Efficiency

Recommended:

- Provide relevant context.
- Avoid repeated information.
- Continue from previous session state.
- Use existing documentation as reference.

Efficiency should support quality, not replace it.

---

## 9. Maintain Long-Term Quality

Consider:

- Maintainability.
- Readability.
- Consistency.
- Future expansion.
- Testing requirements.

Short-term solutions should not create long-term technical debt.

---

## Completion Criteria

Best practices are followed when:

- Implementation quality is maintained.
- Architecture remains protected.
- Changes are easy to review.
- Documentation remains consistent.
- Development workflow remains efficient.
